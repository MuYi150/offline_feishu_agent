# 已知限制与下一阶段计划

## 当前限制

- 只处理本地 Fixture，不读取真实飞书 Wiki、Sheet、Docx、Drive 或联系人数据。
- 附件第一阶段只进入元数据；如果正文关键结论依赖附件内容，结果必须转人工复核。
- 不安装 PaddleOCR，也不提供扫描件 OCR 兜底。Kimi 直接读取成功渲染的页面图。
- 相似性检测只使用 Blocks 或原始 PDF 文字层；图片、截图、扫描 PDF 和内嵌图纸中的文字不会进入摘要或相似度。
- 字符 TF-IDF 只能发现文字和技术词汇重合，不理解原理图语义，也不能自动证明抄袭。0.35 阈值及固定权重仍需用真实知识库语料校准。
- 本地索引只保存可读摘要，不保存历史全文和关键页面；模型的最终判断受摘要覆盖范围限制。后续可增加文本 Embedding，但不应改变“算法召回、模型判断”的职责边界。
- PDF 文本生成器用于测试和缺省输入兜底，不追求还原飞书 Docx 的完整排版。
- SQLite checkpointer 适合单机、本地和小规模工作流，不承担多进程生产调度。
- 跨轮审稿历史目前是按 document_id 分文件的原子 JSON，支持 checkpoint 重试幂等，但未提供多进程同时写同一文档的锁竞争协调。
- 模型自然语言结论具有波动性；真实冒烟测试只校验 Schema、证据引用、业务不变量和产物，不逐字比较。

## 下一阶段飞书适配

新增实现稳定公开协议的 `FeishuDocumentSource`、`FeishuResultSink` 和 `FeishuNotificationSink`，将线上读取与写入放在审稿核心之外。先做只读 dry-run，对文档 token、更新时间和内容哈希建立幂等键；再分阶段开放 Sheet 状态、意见列和消息发送。自动公示、移动知识库节点或修改正文仍需单独审批和权限策略，不与本地审稿默认路径绑定。
